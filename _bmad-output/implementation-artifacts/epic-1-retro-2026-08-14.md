## Findings

### Security (Firebase)

- **F3 [MED] Slug namespace is writable by any authenticated user** — `firestore.rules:81-85` allows `create` on `slugs/{slug}` for `request.auth != null` with no format check and no ownership check against the referenced restaurant. Any authenticated user can squat arbitrary slug keys (namespace DoS / squatting). Update/delete correctly denied; restaurants/tables/bookings rules are otherwise solid (validated shapes, `isOwner`, atomic `validateRestaurantData`). Source: `firestore.rules:81-85`.
- **F10 [LOW] Reset-password account enumeration** — `auth.service.ts:74-75` maps `auth/user-not-found` → "No account found with this email", distinguishable from the generic error, so the reset form leaks whether an email is registered. Story 1-3 flagged this as a patch; the distinct mapping was kept. Source: `auth.service.ts:70-93`, story 1-3 finding list.
- **F9 [LOW] `isFirstSignIn()` string-equality fragility** — `auth.service.ts:58-68` returns `creationTime === lastSignInTime`. Undefined metadata → `false` (safe); string comparison misroutes a returning Google user to `/onboarding` if the two timestamps coincide. Story 1-3 deferred; still open. Source: `auth.service.ts:58-68`.

### Deploy / correctness

- **F4 [MED] Prod widget bundle URL unverified** — `environment.prod.ts:16` still carries the story-default `https://firebase-crackling-fire-4704.web.app/widget/booking-widget.mjs`; Firebase CLI was unauthenticated at story close so the hosting domain was never confirmed. Story 1-7 flagged it as "verify before release" (`1-7-onboarding-completion-deploy.md:162`) but it remains unresolved. Must be confirmed before any real deploy.
- **F5 [MED] Dev embed URL points at the wrong port** — dev/base/e2e `widgetBundleUrl` = `http://localhost:4200/...` (`environment.dev.ts:24`, `environment.ts:21`) but `ng serve` runs on **4210** (`angular.json:125,129`; `playwright.config.ts:49`). A developer copying the embed snippet gets a dead URL. Story 1-7 flagged the ambiguity, did not change it.
- **F12 [LOW] `ng serve` requires `dist/widget` to exist** — `angular.json` assets entry fails on a clean clone until `npm run build:widget` runs once; documented in story 1-7 notes but a real DX trap. Source: `1-7-onboarding-completion-deploy.md:165`.
