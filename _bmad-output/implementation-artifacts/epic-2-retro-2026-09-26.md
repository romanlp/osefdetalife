## Findings

### 1. State Management & Flow Machine
- **F2-1 [LOW] Ephemeral details draft management** (`src/booking/services/booking-flow.service.ts:38-42`, `src/booking/steps/details-step/details-step.component.ts:50-58`):
  In Story 2.4, form state was local to `DetailsStepComponent`, meaning back-then-forward destroyed diner input. Story 2.5 resolved this by lifting `DetailsDraft` into `BookingFlowService`. Re-confirming identical party size or date initially flushed the slot and draft until refined in Story 2.5.
  - *Disposition:* Accept as-is. Lesson for Epic 3: state lifecycle for wizard/funnel flows should be specified at story planning.

### 2. Testing Infrastructure & Test Isolation
- **F2-2 [MED] Full e2e suite concurrency and emulator port contention** (`playwright.config.ts`, `angular.json`):
  During Story 2.5 verification, running the entire Playwright suite sequentially (`npx playwright test`) occasionally suffered from emulator timing collisions or uncleaned Firestore state from prior test fixtures. Port 4210 was also held by host SSH multiplexing.
  - *Disposition:* Defer / Tech Debt. Consider formalizing an e2e pre-flight check or teardown script to verify clean emulator ports and database states between runs.
- **F2-3 [LOW] Duplicate zoned-day date math in test helpers** (`e2e/tests/public-booking-page.spec.ts:18-75`, `src/booking/utils/calendar.ts`):
  Identified originally in Story 2.2 deferrals: e2e test helpers duplicate UTC/timezone calendar math rather than importing from `src/booking/utils`.
  - *Disposition:* Accept as-is. Preserves boundary discipline between test harness and application runtime.

### 3. Architecture & Style Budgets
- **F2-4 [LOW] Component SCSS budget ceiling** (`angular.json:84-90`, `src/booking/pages/booking-page/booking-page.component.scss`):
  Adding CSS classes for step transition indicators pushed `booking-page.component.scss` over the 2.0 kB `anyComponentStyle` budget (2.15 kB). Refactoring to existing Tailwind utility classes resolved the warning and reduced component style footprint.
  - *Disposition:* Accept as-is. Established convention: prefer Tailwind utilities over bespoke component CSS in page shells to respect Angular bundle budgets.
